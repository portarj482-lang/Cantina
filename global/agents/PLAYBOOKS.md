# Agent Playbooks and Learning Paths

One distinct progression per role. Paths start with study, then use synthetic fixtures or already-authorized artifacts for practice, and finish with the role's required output. They do not authorize bounty testing, tool installation, external disclosure, or writes outside the active bounty. Shared requirements in `CONTRACT.md`, `AGENT_SET.md`, and the active bounty always take precedence.

**Levels:** Foundation = understand inputs and vocabulary; Practice = apply the role method to a fixture or permitted artifact; Demonstrate = produce the role's output and have its limits checked. A missing tool or prerequisite means stop, not improvise.

| Agent | Learning path (Foundation → Practice → Demonstrate) | Specialist skills to build | Role-specific rules / exit check |
|---|---|---|---|
| [aderyn-runner](aderyn-runner.md) | Read Aderyn help/SARIF docs → inspect a sample report → run only on approved build copy | Aderyn configuration, SARIF, detector triage | Preserve raw SARIF; report detector counts, not vulnerability truth |
| [bounty-scanner](bounty-scanner.md) | Review Solidity visibility/modifiers → map one contract fixture → map all scoped entrypoints | Source navigation, caller privileges, call/value/state flow | Facts only; every row cites source; no safety or severity verdict |
| [counterexample-tracer](counterexample-tracer.md) | Study Forge traces/reverts → replay a fixture counterexample → trace exact failure and reachability | Test minimization, revert decoding, state-transition tracing | A solver trace is not exploitable until legal public-entry reachability is shown |
| [deep-scanner](deep-scanner.md) | Read hypothesis evidence standards → challenge a toy claim → return a claim/evidence disposition | Guard tracing, alternative explanations, impact boundaries | One lead at a time; missing evidence is UNRESOLVED, not REFUTED |
| [echidna-executor](echidna-executor.md) | Learn property syntax and corpus behavior → run a sample harness → preserve a minimized failing sequence | Echidna properties, corpus management, counterexample reduction | Tool must be OK; preserve seed/config/raw sequence; no finding verdict |
| [forge-fuzz-runner](forge-fuzz-runner.md) | Study Foundry fuzz controls → exercise a local fixture with two seeds → report both outputs | Stateful fuzzing, seed control, shrinking | Use manifest seeds; zero matched tests is `no_tests`, never pass |
| [forge-inspect-layout](forge-inspect-layout.md) | Study Solidity storage/transient layout → inspect sample JSON → map only manifest contracts/pairs | Slot/offset/type interpretation, `tstore`/`tload` search | Do not infer exploitability from layout differences or guess contract names |
| [forge-invariant-runner](forge-invariant-runner.md) | Learn handlers/invariant configuration → validate an invariant on a fixture → run broken control and target | Stateful invariants, handler coverage, counterexample capture | Record runs/depth/seed; a passing invariant is useful only if the broken control fails |
| [forge-tester](forge-tester.md) | Read PoC non-negotiables → write a toy exploit/kill pair → author a candidate-specific test suite | Foundry test design, exact deltas, attacker modeling, controls | Author tests only; never certify own PoC, alter scope, or assign severity |
| [forge-unit-runner](forge-unit-runner.md) | Study Forge test JSON/filters → run a fixture suite → report status and failure context | Test selection, JSON parsing, failure localization | Build copy only; zero tests is `no_tests`; preserve output and command |
| [g1-idl-mapper](g1-idl-mapper.md) | Learn Anchor IDL/discriminators → map a fixture instruction → produce scoped interface/account map | IDL parsing, account metas, PDA seeds, CPI mapping | Map only; never infer exploitability or invent discriminator/account data |
| [g2-binding-checker](g2-binding-checker.md) | Study Anchor constraints/PDA derivation → verify sample bindings → issue binding ledger | Signer/owner/mint/PDA validation, cross-pool isolation | IDL omission alone is not proof of a missing runtime check; dynamic evidence precedes promotion |
| [g3-conservation-checker](g3-conservation-checker.md) | Review integer accounting/rounding → calculate fixture transitions → report exact invariant deltas | Lamport/token accounting, fees, curve reserves, overflow/rounding | Integer arithmetic only; no live accounts or seed changes to force a pass |
| [g4-validator-runner](g4-validator-runner.md) | Study local-validator lifecycle → load fixture program/accounts → capture reproducible logs | Solana validator setup, account fixtures, slot/compute logs | Local environment only; verify binary hash and program-ID mapping before launch |
| [g5-solana-poc](g5-solana-poc.md) | Study Anchor instruction builders → author a control transaction → write/replay candidate PoC | Transaction construction, test signers, account metas, post-state assertions | No business-logic reimplementation, placeholders, live writes, or self-approval |
| [hallucination-dropper](hallucination-dropper.md) | Study citation/source mapping → check a sample claim → verify candidate identifiers/quotes | Citation validation, AST/name matching, drop-reason logging | Drop unsupported claims, not valid findings; preserve exact reason and source artifact |
| [halmos-arithmetic](halmos-arithmetic.md) | Learn Halmos assertion model → analyze arithmetic fixture → save bounded result | SMT basics, integer arithmetic, rounding/truncation properties | Run only existing `check_arith_*` tests; state solver/time/loop bounds |
| [halmos-counterexample](halmos-counterexample.md) | Study symbolic inputs/preconditions → classify fixture models → hand off legal replay values | Model decoding, input constraints, reachability preconditions | `LEGAL-CANDIDATE` is not an exploit; identify impossible states explicitly |

| [halmos-proofing](halmos-proofing.md) | Learn solver outcomes/bounds → classify sample SAT/UNSAT/unknown → publish with limits | SMT result interpretation, proof bounds, artifact traceability | Never describe bounded success as proof of system safety |
| [hypothesis-analyst](hypothesis-analyst.md) | Read threat-model/invariant examples → draft a falsifiable fixture claim → write H-### | Attacker modeling, invariant formulation, predictions/falsifiers | No tool execution, PoC authorship, severity, or promotion; unsupported items stay UNRESOLVED |
| [independent-falsifier](independent-falsifier.md) | Learn adversarial review → challenge an unrelated sample claim → document strongest refutation attempt | Independent source review, reachability, guard and impact falsification | Do not follow the original claim; a failed test refutes only its tested prediction |

| [known-overlap-annotator](known-overlap-annotator.md) | Review issue-matching criteria → compare a sample pair → classify exact/adjacent/none | Root-cause comparison, exclusion matching, evidence quoting | Never delete/suppress a candidate; distinguish `COVERS-EXACTLY` from `ADJACENT` |
| [known-tags-scan](known-tags-scan.md) | Learn configured regex semantics → scan a fixture → emit exact tag matches and copied issue list | Regex validation, source/scope extraction | Use manifest patterns only; preserve program text verbatim; no duplicate verdict |
| [layout-diff](layout-diff.md) | Study Solidity inheritance/slot layout → compare fixture JSON → report aligned deltas | Storage-slot comparison, type encoding, delegatecall context | Compare declared pairs only; mismatch is a lead, not exploitability |
| [lead-security-auditor](lead-security-auditor.md) | Learn stage outputs/gates → plan a mock case → assemble an evidence-linked draft | Stage planning, evidence synthesis, source/impact separation | Delegate bounded tasks only when authorized; never set Ready/Submitted or let scores decide |

| [pathway-scout-oracle](pathway-scout-oracle.md) | Validate scope → enumerate source files → discover entrypoints → construct pathways → prioritize review queue → write pathways.json | Scope-first, evidence-backed, read-only by default | Never report `entrypoints_mapped:true` without verified source evidence; distinguish `inferred` from `verified`; use `BLOCKED` when scope missing |

| [recon](recon.md) | Study discovery scope and safety gates → verify fixture workspace and inventory → serialize validated recon.json | Scope discovery, Solidity inventory, atomic JSON validation | Dry-run by default; no false successful completion on missing directories or traversal errors |

| [sarif-collector](sarif-collector.md) | Learn SARIF structure/locations → validate fixture reports → merge valid results and log rejects | Schema validation, result provenance, dedup awareness | Never drop silently; preserve source tool identity and rejection reason |

## Common graduation check

The agent can explain its inputs, method, output schema, allowed scope, and one way its result could mislead. The lead or human reviews its first real artifact. Reading the path does not mean the agent is trained or a tool is ready.
