## 1. Hypothesis Formulation
The hypothesis queried whether:
1. When the Guardian blacklists a dispute game via `blacklistDisputeGame`, the game's claims remain valid for withdrawals or anchor updates.
2. A subsequent dispute game can use a blacklisted game as its parent.
3. An honest child game can advance the dispute progression monotonically past the blacklisted game.

---

## 2. Invariant & Source Analysis

In `AnchorStateRegistry.sol` and `AggregateVerifier.sol`:
```solidity
function isGameClaimValid(IDisputeGame _game) public view returns (bool) {
    if (!isGameProper(_game)) return false;
    // ...
}

function isGameProper(IDisputeGame _game) public view returns (bool) {
    if (!isGameRegistered(_game)) return false;
    if (isGameBlacklisted(_game)) return false;
    // ...
}

// In AggregateVerifier:
if (parentAddress() != address(ANCHOR_STATE_REGISTRY)) {
    IDisputeGame parentGame = IDisputeGame(parentAddress());
    if (!_isValidGame(parentGame)) revert InvalidParentGame();
}
```

1. Blacklisting immediately flips `isGameBlacklisted = true`, causing `isGameProper` and `isGameClaimValid` to evaluate to `false`.
2. Setting anchor state with a blacklisted game reverts with `AnchorStateRegistry_InvalidAnchorGame()`.
3. Creating a child game with a blacklisted parent reverts with `InvalidParentGame()`.
4. The dispute pipeline enforces strict monotonicity: anchor updates require $game.l2SequenceNumber > currentAnchorBlock$. An honest parent game at block 100 allows honest child games at block 200 to advance the anchor state cleanly.
