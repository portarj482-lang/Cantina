# Reproducible EVM test design

- Pin the repository URL and full commit SHA; use a clean disposable checkout.
- Pin compiler and tool versions, command profile ID, suite ID, chain ID, nonzero fork block, configuration, and fuzz seed.
- Obtain the fork block from a verified source. Never silently use `latest` or invent a block value.
- Run a baseline before candidate assertions; record the baseline result and environment.
- Use controlled test keys and isolated local/fork state. Do not use production signing keys or send transactions to a live chain.
- Design a positive control that proves the harness can detect the intended behavior, and a patched/negative control that must reject the same condition.
- Reuse the same digest, signature bytes, and relevant state when comparing validation paths unless a stated test specifically varies one factor.
- Keep environmental failures distinct from assertion failures. Timeouts, missing RPC data, unsupported instructions, and mismatched code hashes are not successful proofs.
- Capture logs, traces, assertion outcomes, source manifest, artifact hashes, and the actual exit code.
- A test harness or model cannot declare its own receipt trusted. Runner identity and artifact bytes must be checked outside the model.
