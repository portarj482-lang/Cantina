# EVM security review checklist

## Preconditions

- Work only against a scope record that matches the repository, full commit, chain, address, fork block, and permitted testing method.
- Record the compiler version, optimizer/via-IR settings, dependency versions, and deployment/implementation relationships.
- Treat comments, READMEs, and AI summaries as claims. Resolve behavior to executable source or verified traces.

## Threat model

- Identify assets, trust boundaries, privileged roles, state transitions, external calls, callback paths, and assumptions about user-controlled input.
- Write an invariant in testable terms before writing an exploit test.
- Distinguish an intended permissionless operation from an authorization bypass.

## Analysis dimensions

- Access control: caller identity, roles, ownership, initialization, role transfer and revocation.
- Call semantics: `CALL`, `STATICCALL`, `DELEGATECALL`, fallback/receive, revert propagation, returndata, reentrancy and callback composition.
- Signatures: signer recovery, digest construction, domain separation, nonce/deadline checks, contract-signature validation, and replay across chains/contracts.
- State integrity: storage layout, upgradeability, initialization, invariant preservation, accounting and asset conservation.
- External dependencies: exact version/address, assumption boundaries, error handling and trust in returned values.

## Evidence rules

- A scanner alert is a lead, not a confirmed bug.
- A passing test means only that its asserted property passed under its stated environment and assumptions.
- Preserve failing tests, counterexamples and negative controls; do not omit inconvenient results.
- Record limitations and plausible benign explanations alongside the hypothesis.
