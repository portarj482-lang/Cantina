# Hypothesis Evaluation: H-079

- **ID:** H-079
- **Target:** `AggregateVerifier` ([`contracts/src/L1/proofs/AggregateVerifier.sol`](file:///home/nova/projects/cantina/bounties/base/contracts/src/L1/proofs/AggregateVerifier.sol))
- **Actor:** Malicious prover / challenge race adversary
- **Prediction:** An attacker can inject proofs, challenge data, or intermediate roots into a dispute game that has already resolved `DEFENDER_WINS`, overturning the dispute outcome.
- **Status:** KILLED / REFUTED (Defensive Protocol Invariant Validated)
- **Kill Category:** DISPUTE_RESOLUTION_FINALITY_AND_CHALLENGE_LOCKOUT
- **Date:** 2026-10-25

---

## 1. Hypothesis Formulation
The hypothesis queried whether:
1. `AggregateVerifier.challenge` permits post-resolution challenges with alternative ZK proofs.
2. An attacker can load unauthorized proof bytes or alter dispute status after `resolve()` has been executed.

---

## 2. Invariant & Source Analysis

In `AggregateVerifier.sol`:
```solidity
function challenge(
    bytes calldata proofBytes,
    uint256 intermediateRootIndex,
    bytes32 intermediateRootToProve
) external {
    // Can only challenge a game that has not been challenged or resolved yet.
    if (status != GameStatus.IN_PROGRESS) revert ClaimAlreadyResolved();

    // This game cannot be blacklisted or retired.
    if (!_isValidGame(IDisputeGame(address(this)))) revert InvalidGame();
    // ...
}
```

The protocol enforces:
1. `status == GameStatus.IN_PROGRESS`: Once a game resolves, its status permanently transitions to `DEFENDER_WINS` or `CHALLENGER_WINS`.
2. Any challenge invocation after resolution immediately reverts with `ClaimAlreadyResolved()`.
