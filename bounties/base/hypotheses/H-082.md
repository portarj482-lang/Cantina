# Hypothesis Evaluation: H-082

- **ID:** H-082
- **Target:** `SpendPermissionManager` ([`spend-permissions/src/SpendPermissionManager.sol`](file:///home/nova/projects/cantina/bounties/base/spend-permissions/src/SpendPermissionManager.sol))

- **Prediction:** An attacker can spend beyond the approved allowance in a single period, trigger unauthorized resets, cross-contaminate allowances across different permission salts, or spend after explicit permission revocation.
- **Status:** KILLED / REFUTED (Defensive Protocol Invariant Validated)
- **Kill Category:** ALLOWANCE_MONOTONICITY_SALT_ISOLATION_AND_REVOCATION_IMMUTABILITY

## 1. Hypothesis Formulation
The hypothesis queried whether:
1. Spenders can exceed the periodic `allowance` within a single period window.
2. Spending under permission with `salt: 1` deducts or impacts allowance under permission with `salt: 2`.
3. In the subsequent period, the available allowance fails to reset cleanly.
4. Calling `revoke` allows further spending if executed via a router.

---

## 2. Invariant & Source Analysis

In `SpendPermissionManager.sol`:
```solidity
function _useSpendPermission(SpendPermission memory spendPermission, uint256 value) internal {
    if (!isValid(spendPermission)) revert UnauthorizedSpendPermission();

    PeriodSpend memory currentPeriod = getCurrentPeriod(spendPermission);
    uint256 totalSpend = value + uint256(currentPeriod.spend);

    if (totalSpend > spendPermission.allowance) {
        revert ExceededSpendPermission(totalSpend, spendPermission.allowance);
    }

    currentPeriod.spend = uint160(totalSpend);
    _lastUpdatedPeriod[hash] = currentPeriod;
}
```

1. Permissions are identified by `hash = getHash(spendPermission)`, which includes `salt`. Permissions differing by salt map to independent storage slots, ensuring complete cross-permission isolation.
2. `totalSpend > allowance` immediately reverts with `ExceededSpendPermission(totalSpend, allowance)`.
3. Period calculation derives start and end times dynamically from `spendPermission.start` and `spendPermission.period`. When `block.timestamp >= lastPeriodEnd`, a fresh period spend of 0 is returned, resetting allowance cleanly.
4. `revoke()` sets `_isRevoked[hash] = true`. `isValid` returns `false` if `_isRevoked[hash]` is true, causing any subsequent `spend` to revert with `UnauthorizedSpendPermission()`.
