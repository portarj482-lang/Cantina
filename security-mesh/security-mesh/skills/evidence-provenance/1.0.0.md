# Evidence provenance and claim hygiene

- Split report language into claims and link each material claim to one or more evidence IDs.
- A source reference must identify repository, full commit SHA, normalized path, line range, and a verified source excerpt/hash.
- A tool result must contain a real run ID, known runner identity, approved suite/command profile, pinned environment, exit code, assertion outcomes, and artifact hashes.
- Verify artifact bytes against their SHA-256 digest; an artifact filename, receipt label, screenshot, or AI-generated summary is not a hash proof.
- Store `execution_status`, `finding_status`, `review_status`, `approval_status`, and `submission_status` separately.
- Preserve failed, rejected, and inconclusive outcomes. Never translate timeout into pass or process exit code zero into vulnerability confirmation.
- Do not remove an uncertainty merely to make a report more persuasive. Use `not_applicable` only when an approved policy rule supports it and the reason is recorded.
- An accepted independent review and a human submission authorization are separate acts. Neither should be generated by the report writer.
