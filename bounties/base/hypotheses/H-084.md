## 1. Hypothesis Formulation
The hypothesis queried whether:
1. `FeeVault.withdraw()` can be called when contract balance is less than `minWithdrawalAmount`.
2. Parameter setters (`setMinWithdrawalAmount`, `setRecipient`, `setWithdrawalNetwork`) can be called by unauthorized accounts to hijack fee distribution.
3. Funds can be diverted away from `recipient` during an L2 or L1 withdrawal transaction.

---

## 2. Invariant & Source Analysis

In `FeeVault.sol`:
```solidity
function setMinWithdrawalAmount(uint256 _newMinWithdrawalAmount) external {
    _assertOnlyProxyAdminOwner();
    // ...
}

function setRecipient(address _newRecipient) external {
    _assertOnlyProxyAdminOwner();
    // ...
}

function withdraw() external returns (uint256 value_) {
    require(
        address(this).balance >= minWithdrawalAmount,
        "FeeVault: withdrawal amount must be greater than minimum withdrawal amount"
    );

    value_ = address(this).balance;
    totalProcessed += value_;
    address recipientAddr = recipient;

    if (withdrawalNetwork == Types.WithdrawalNetwork.L2) {
        bool success = SafeCall.send(recipientAddr, value_);
        require(success, "FeeVault: failed to send ETH to L2 fee recipient");
    } else {
        IL2ToL1MessagePasser(payable(Predeploys.L2_TO_L1_MESSAGE_PASSER)).initiateWithdrawal{ value: value_ }({
            _target: recipientAddr, _gasLimit: _WITHDRAWAL_MIN_GAS, _data: hex""
        });
    }
}
```

1. `withdraw()` strictly enforces `address(this).balance >= minWithdrawalAmount`. Any premature call reverts immediately.
2. Parameter mutations are restricted by `_assertOnlyProxyAdminOwner()`. Unauthorized callers revert.
3. When withdrawal executes on L2, `SafeCall.send` transfers 100% of the contract balance directly to `recipient`, increments `totalProcessed`, and leaves contract balance at 0.
